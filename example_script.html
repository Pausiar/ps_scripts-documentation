📚 PS Example Script

Este es un ejemplo de documentación creada con TEMPLATE.html. Demuestra cómo documentar correctamente un script de FiveM.

Instalación Configuración
✅ Nota: Este es un script de ejemplo para demostrar cómo usar el template de documentación. No es un script real.

✨ Características Principales

  • Sistema modular y fácil de configurar
  • Compatible con ESX Legacy y QBCore
  • Interfaz de usuario moderna con NUI
  • Optimizado para rendimiento (0.00ms en idle)
  • Soporte multiidioma (ES/EN)
  • Base de datos MySQL integrada
  • Sistema de permisos flexible
  • Logs completos de actividad

📋 Requisitos

  • Framework: ESX Legacy 1.9+ o QBCore
  • Base de datos: MySQL 5.7+ / MariaDB 10.3+
  • Dependencias:
    • es_extended (para ESX) o qb-core (para QBCore)
    • oxmysql o mysql-async
    • ox_lib (opcional, pero recomendado)
  • Versión del servidor: FiveM artifact 5000+

⚙️ Instalación

1. Descarga el script

Descarga la última versión desde el repositorio de GitHub o tu plataforma de distribución.

2. Extrae los archivos

Extrae el contenido en tu carpeta de recursos:

server-data/resources/[pausiar]/ps_example/

3. Importa la base de datos

Importa el archivo SQL incluido en tu base de datos:

mysql -u usuario -p nombre_base_datos < ps_example.sql

O usa tu gestor de bases de datos favorito (HeidiSQL, phpMyAdmin, etc.)

4. Configura el archivo

Edita el archivo config.lua según tus necesidades (ver sección de configuración más abajo).

5. Añade al server.cfg

Agrega la siguiente línea a tu server.cfg:

ensure ps_example
💡 Tip: Asegúrate de que el script se cargue después de tu framework (ESX o QBCore) y sus dependencias.

6. Reinicia el servidor

Reinicia tu servidor y el script estará listo para usar.

🔧 Configuración

El archivo config.lua contiene todas las opciones configurables. A continuación se muestran las opciones principales:

Configuración General

Config = {} -- Framework: 'esx' o 'qbcore' Config.Framework = 'esx' -- Idioma: 'es' (español) o 'en' (inglés) Config.Locale = 'es' -- Activar debug (muestra mensajes en consola) Config.Debug = false -- Usar ox_lib para notificaciones y menús Config.UseOxLib = true

Configuración de Funcionalidades

-- Activar sistema de logs Config.EnableLogs = true -- Webhook de Discord para logs (opcional) Config.DiscordWebhook = 'https://discord.com/api/webhooks/...' -- Distancia de interacción (en metros) Config.InteractionDistance = 2.5 -- Cooldown entre usos (en segundos) Config.Cooldown = 60

Configuración de Ubicaciones

-- Ubicaciones de interacción Config.Locations = { { coords = vector3(195.17, -933.77, 30.69), heading = 180.0, blip = { enabled = true, sprite = 280, color = 3, scale = 0.8, label = "Example Location" } }, -- Añadir más ubicaciones aquí }
⚠️ Importante: Después de modificar la configuración, debes reiniciar el script o el servidor para que los cambios tengan efecto.

Permisos

Los siguientes permisos están disponibles (según tu framework):

ESX:

  • ps_example.user - Acceso básico de usuario
  • ps_example.admin - Acceso administrativo completo

QBCore:

  • Rank "user" - Acceso básico
  • Rank "admin" o "god" - Acceso administrativo

Exportaciones (para desarrolladores)

El script exporta las siguientes funciones para uso de otros recursos:

🔍 Solución de Problemas

Problema: El script no aparece en el servidor

Solución:

  • Verifica que la línea ensure ps_example esté en tu server.cfg
  • Comprueba que el nombre de la carpeta sea exactamente ps_example
  • Revisa la consola del servidor en busca de errores

Problema: Error de base de datos

Solución:

  • Asegúrate de haber importado el archivo ps_example.sql
  • Verifica que oxmysql o mysql-async estén funcionando correctamente
  • Comprueba las credenciales de tu base de datos

Problema: Los comandos no funcionan

Solución:

  • Verifica que tengas los permisos necesarios
  • Asegúrate de que el framework (ESX/QBCore) esté correctamente configurado
  • Intenta reiniciar el script con restart ps_example

Problema: Bajo rendimiento / Lag

Solución:

  • Reduce Config.InteractionDistance si es muy alto
  • Desactiva Config.Debug en producción
  • Verifica que no haya conflictos con otros scripts
⚠️ Recuerda: Siempre haz una copia de seguridad antes de hacer cambios en tu servidor.

❓ Preguntas Frecuentes

¿Es compatible con otros scripts?

Sí, el script está diseñado para ser compatible con la mayoría de los recursos de FiveM. Si encuentras algún conflicto, por favor repórtalo.

¿Puedo modificar el script?

Sí, puedes modificar el script para adaptarlo a tus necesidades. Sin embargo, se recomienda mantener una copia del original.

¿Hay soporte multiservidor?

Sí, cada servidor tendrá su propia instancia independiente siempre que usen bases de datos separadas.

¿Funciona en servidores OneSync?

Sí, el script es totalmente compatible con OneSync y OneSync Infinity.
